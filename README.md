# TankBoost — стартовый каркас сайта бустинга «Мир танков»

Минимальный, но рабочий шаблон: Node.js + Express + SQLite (better-sqlite3) + ванильный фронтенд.
Предназначен для дальнейшей разработки — многие места помечены `TODO`.

## Структура

```
wot-boost/
├── src/
│   ├── server.js            # точка входа: сессии, CSRF, роутинг, статика
│   ├── config.js            # конфиг из переменных окружения

│   ├── services.js          # доступ к каталогу услуг

│   ├── receipt.js           # (опционально) чек 54-ФЗ
│   ├── db/index.js          # СЛОЙ ДАННЫХ (схема + все запросы) — меняется целиком при смене БД

├── data/services.json       # каталог услуг (цены в рублях)
```

## Запуск

```bash
cp .env.example .env      # заполнить SESSION_SECRET и т.д.
npm install
npm start                 # http://127.0.0.1:3000
npm run dev               # с автоперезапуском (node --watch)
npm run check             # синтаксическая проверка JS
npm test                  # тесты оплаты (node --test, без сети)
```

Требуется Node.js 22 (`engines`, `.node-version`; под него есть prebuilt `better-sqlite3`). Для `bcrypt` и `better-sqlite3` нужны prebuilt-бинарники или build-tools (python3, make, g++).

Локально по http выставьте `COOKIE_SECURE=false`, иначе браузер не сохранит cookie. В проде — `true` (за HTTPS через nginx).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | порт Node (по умолчанию 3000, слушает только 127.0.0.1) |
| `NODE_ENV` | `production` включает обязательность `SESSION_SECRET` и Secure-cookie |
| `SESSION_SECRET` | секрет подписи cookie сессии |
| `COOKIE_SECURE` | флаг Secure для cookie |
| `DB_PATH` | путь к файлу SQLite |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | ключи ЮKassa. Пустые → **MOCK-режим** (тестовая оплата, без денег) |
| `PUBLIC_BASE_URL` | публичный https-адрес сайта для `return_url` (на Render по умолчанию `RENDER_EXTERNAL_URL`) |
| `YOOKASSA_RECEIPT` | `true` — передавать чек 54-ФЗ (см. ниже), по умолчанию выключено |
| `YOOKASSA_VAT_CODE`, `YOOKASSA_TAX_SYSTEM_CODE`, `YOOKASSA_PAYMENT_SUBJECT`, `YOOKASSA_PAYMENT_MODE` | параметры чека |
| `YOOKASSA_API_URL` | (только для тестов) адрес API, по умолчанию `https://api.yookassa.ru/v3` |

Секреты храните только в `.env` (он в `.gitignore`).

## API

Все не-GET запросы требуют заголовок `X-CSRF-Token` (берётся из `GET /api/state`).
Суммы в ответах БД — в **копейках**, цены каталога — в рублях.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/register` | `{email, password, pdConsent:true}` |
| POST | `/api/login` | `{email, password}` |
| POST | `/api/logout` | |
| GET | `/api/state` | `{authenticated, user, csrfToken}` |
| GET/POST | `/api/profile` | только `display_name, game_nickname, game_server, telegram` |
| GET | `/api/services`, `/api/services/:id` | каталог |
| GET/POST | `/api/orders` | `{items:[{serviceId, qty, options}], comment}`; цена считается на сервере |
| GET | `/api/billing` | баланс и платежи |
| POST | `/api/payments` | `{orderId}` → создаёт платёж по своему заказу, `{paymentId, status, confirmationUrl}`; сумма берётся с сервера |
| GET | `/api/payments/:id` | статус своего платежа; если `pending` — перепроверяется у ЮKassa (используется страницей возврата) |
| POST | `/api/payments/webhook` | уведомления ЮKassa (без CSRF; подлинность — повторным запросом платежа по API) |
| GET/POST | `/api/payments/mock/:pid[/result]` | только MOCK-режим: данные/результат тестовой оплаты |

## Оплата картами «Мир», Visa, Mastercard (ЮKassa)

Реализовано через [ЮKassa API v3](https://yookassa.ru/developers/api): платёж с `confirmation.type=redirect`,
`capture=true`, сумма в RUB, `metadata.order_id`. Способ оплаты **не** фиксируется — пользователь выбирает его
на защищённой странице ЮKassa (карты «Мир», Visa, Mastercard, СБП и др. — по тому, что включено в магазине).
**Номера карт никогда не попадают на наш сервер** — ввод карты только на странице ЮKassa.

### Как это работает
1. В кабинете у заказа в статусе «Ожидает оплаты» кнопка «Оплатить» → `POST /api/payments {orderId}`.
   Сумма берётся из заказа на сервере (он собран по `data/services.json`); от клиента принимается только id заказа,
   чужие заказы недоступны (404). Повторный клик возвращает тот же платёж (идемпотентно, ключ `Idempotence-Key` хранится в БД).
2. Пользователь уходит на страницу ЮKassa и оплачивает, затем возвращается на `/payment-return.html`.
   Страница опрашивает `GET /api/payments/:id`; сервер **заново запрашивает платёж у ЮKassa** и обновляет статус.
3. Параллельно ЮKassa шлёт `POST /api/payments/webhook`. Телу уведомления **не доверяем**: берём только `object.id`,
   запрашиваем платёж через API и сверяем id, валюту (RUB), сумму и `metadata.order_id` с нашей записью.
   Несовпадение → отказ (400), неизвестный id → 404. Заказ становится `paid` в одной транзакции и только один раз;
   повторные уведомления безопасны; успешный платёж не откатывается поздним `canceled`.
4. Статусы платежа: `pending` (ожидает оплаты) / `succeeded` (оплачено) / `canceled` (отменено); в UI — на русском.

БД: таблица `payments` расширена колонками `order_id, confirmation_url, idempotence_key, updated_at`, в `orders` добавлено
`paid_at`; миграция при старте безопасна для существующей базы (`ALTER TABLE ... ADD COLUMN`, если колонки нет).
Rate limit: создание платежа 30/15 мин, статус 60/мин, вебхук 120/мин (на IP).

### MOCK-режим (без ключей)
Если `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` не заданы, «Оплатить» ведёт на локальную страницу
`/mock-checkout.html` с крупной пометкой **TEST MODE — деньги не списываются** и двумя кнопками: «успех» / «отказ».
Остальной путь (проверка статуса у «провайдера», идемпотентность, вебхук) тот же; «провайдер» имитируется таблицей
`mock_provider_payments`. Страница доступна только владельцу платежа, полей для ввода карты нет.
Как только ключи заданы, mock-эндпоинты отвечают 404 и платежи идут в настоящую ЮKassa.

### Как подключить боевую оплату — что нужно получить у владельца бизнеса
1. **Регистрация в ЮKassa** ([yookassa.ru](https://yookassa.ru)) — принимать платежи можно как **самозанятый (НПД)**, **ИП** или **ООО**
   (физлицо без статуса — нельзя). Нужно заполнить анкету магазина (сайт, описание услуг), загрузить документы/реквизиты
   и **заключить договор** с ЮKassa (онлайн, обычно через ЭП/подтверждение в кабинете). Сайт должен содержать оферту,
   контакты, условия возврата — ЮKassa проверяет это при модерации (см. заглушки `public/offer.html` и др.).
   Проверьте, что вид деятельности (бустинг игровых аккаунтов) проходит модерацию — риск отказа есть.
2. После одобрения в личном кабинете: **Интеграция → Ключи API** — взять `shopId` и выпустить **секретный ключ**
   (показывается один раз!). Это `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
3. На хостинге (Render Dashboard → Environment) задать `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `PUBLIC_BASE_URL=https://<ваш домен>`.
   Секреты **только** в переменных окружения, не в git.
4. **Webhook**: **Интеграция → HTTP-уведомления** → URL `https://<ваш-домен>/api/payments/webhook`
   (только HTTPS, порт 443/8443), события **`payment.succeeded`** и **`payment.canceled`**.
5. Сначала проверьте всё в **тестовом магазине ЮKassa** (создаётся в кабинете, свои shopId/secret; платежи идут с `test: true`).
   Для тестовых уведомлений ЮKassa советует отдельный URL. Не выполняйте заказы, оплаченные в тесте.

### 54-ФЗ: чеки
Если продавец — ИП/ООО, чек обязателен: либо через онлайн-кассу ЮKassa («Чеки от ЮKassa»), либо через свою кассу.
В этом случае в платёж нужно передавать объект `receipt` (`customer.email`/`phone`, `items[]` с `description, quantity, amount,
vat_code, payment_subject, payment_mode`, при необходимости `tax_system_code`). Билдер готов в `src/receipt.js` и **выключен**:
включается `YOOKASSA_RECEIPT=true` + `YOOKASSA_VAT_CODE` (1 — без НДС, 2 — 0%, 3 — 10%, 4 — 20% …),
`YOOKASSA_TAX_SYSTEM_CODE` (1 ОСН, 2 УСН «доходы», 3 УСН «доходы−расходы», 5 ЕСХН, 6 Патент; можно не задавать, если
система налогообложения указана в кабинете), `YOOKASSA_PAYMENT_SUBJECT` (по умолчанию `service`), `YOOKASSA_PAYMENT_MODE`
(по умолчанию `full_payment`). Email покупателя берётся из аккаунта. **Что выбрать — решает бухгалтер/владелец**; значения по
умолчанию — лишь разумная заготовка. Самозанятый (НПД) формирует чек сам в приложении «Мой налог» — тогда `receipt` не нужен
(в ЮKassa для самозанятых есть автоформирование чеков).

### Тестовые карты ЮKassa (только в тестовом магазине!)
Срок действия — любая будущая дата, CVC и код 3-D Secure — любые цифры. Настоящие карты в тестовом магазине использовать нельзя.

| Номер | Тип | 3-D Secure |
|---|---|---|
| 2200 0000 0000 0004 | Мир | да |
| 2202 4743 0132 2987 | Мир | нет |
| 5555 5555 5555 4444 | Mastercard | нет |
| 4111 1111 1111 1111 | Visa | нет |

Отказы: Мир `2200 0000 0000 0053` — `insufficient_funds`, `2200 0000 0000 0012` — `3d_secure_failed`,
`2200 0000 0000 0038` — `card_expired`. Полный список — [документация ЮKassa: тестирование](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).

### Тесты
`npm test` (Node 22) — `node --test` с подменённым `fetch`, без реальных запросов: создание платежа (сумма с сервера, заголовки,
metadata), идемпотентность, чужие заказы, вебхук (неизвестный id, подделка статуса, неверные сумма/валюта/order_id), отмена,
повтор вебхука, mock-режим, миграция старой БД, билдер чека.
